# Aerial Silks Video Catalog

A production-ready React Native (TypeScript) application for importing, organizing, and reviewing aerial silks training videos entirely on device. The v1 release focuses on local media management, rich metadata, Realm persistence, and resilient background imports without any cloud services or thumbnail generation.

## Why bare React Native?

The app targets deep file-system access, Realm, and native video playback. A bare React Native template keeps the native projects under our control and makes it straightforward to install native modules such as `realm`, `react-native-fs`, `react-native-video`, and `react-native-image-picker` without waiting for Expo config plugins. Bare RN also simplifies platform-specific permission prompts and background import logic.

## Key capabilities

- Import videos from the system file picker or media library.
- Copy every selected file into the app sandbox and persist metadata in Realm.
- Deduplicate imports with a lightweight content signature and notify the user when a video already exists.
- Browse a searchable, filterable list of videos (text search, tag filtering, sort by date/name/size).
- Inspect video details, play content inline, manage tags, write notes with autosave, and add simple bookmarks.
- Resilient import queue that tracks progress, survives backgrounding, and exposes status to the UI.
- Realm schema (Video, Tag, VideoTag, Marker, Collection) with a schema version and sample migration.
- Unit tests covering the repository layer and the import queue orchestration.

## Getting started

```bash
# Install dependencies
npm install

# Start Metro
npm start

# Launch platforms
npm run ios
npm run android

# Quality gates
npm run lint
npm run typecheck
npm test
```

The Android project downloads the Gradle wrapper JAR on first use to keep binary artifacts out of version control. If the download fails (for example, when `curl`, `wget`, or PowerShell are unavailable) follow the on-screen instructions or fetch `gradle-wrapper-<version>.jar` from https://services.gradle.org/distributions/ manually into `android/gradle/wrapper/`.

Metro should run in its own terminal window. Use a second terminal for the platform commands. The project ships with TypeScript strict mode enabled, ESLint, and Prettier. Tests rely on Jest with mocks for the native modules used by the import pipeline.

## Permissions & native configuration

### iOS

- Add the following to `ios/AerialSilksCatalog/Info.plist`:
  - `NSPhotoLibraryUsageDescription` – explain why media library access is required.
  - `NSPhotoLibraryAddUsageDescription` if you later enable exports.
- `react-native-video` requires AVFoundation; the default template includes the necessary linker flags.
- Realm works out of the box after running `pod install` inside the `ios` directory.

### Android

- Update `android/app/src/main/AndroidManifest.xml`:
  - For API < 33 add `READ_EXTERNAL_STORAGE`; for API 33+ add `READ_MEDIA_VIDEO`.
  - Add `WRITE_EXTERNAL_STORAGE` only if future features require exporting files.
- The import queue uses scoped storage friendly APIs via `react-native-document-picker` and `react-native-image-picker`. Ensure the `android:exported` flags in `AndroidManifest.xml` remain as generated by the CLI.
- Generate a local debug keystore before running `npm run android`; the repository intentionally ignores `android/app/debug.keystore` to avoid committing binaries. Create one with:

  ```bash
  keytool -genkeypair \
    -v \
    -keystore android/app/debug.keystore \
    -alias androiddebugkey \
    -storepass android \
    -keypass android \
    -keyalg RSA \
    -keysize 2048 \
    -validity 10000
  ```

  Accept the default certificate prompts or customize as needed.

## Realm schema & migrations

- Schema lives in `src/lib/db/models.ts`. Versioning is configured in `src/lib/db/realm.ts` (`SCHEMA_VERSION = 1`).
- The sample migration demonstrates how to backfill the `contentSignature` field when upgrading from older versions.
- To extend the schema:
  1. Add or update the object model in `models.ts`.
  2. Bump `SCHEMA_VERSION` in `realm.ts`.
  3. Update `onMigration` to transform existing data.
  4. Extend repositories and tests accordingly.
- During development you can inspect the local database with [Realm Studio](https://www.mongodb.com/docs/realm/studio/). Point the tool to the `.realm` file stored under the app’s document directory (`/data/data/<app-id>/files/` on Android, `Library/Application Support/` on iOS).

## Import pipeline overview

1. User picks one or more videos using the file picker or media library adapter (`src/lib/files/picker.ts`).
2. `VideoImportQueue` enqueues each selection, ensures the sandbox storage folder exists, and copies the file into `DocumentDirectoryPath`.
3. Metadata (`size`, `duration`, `createdAt`) is extracted via `src/lib/files/metadata.ts`. Duration currently relies on a native module stub—unknown durations are stored as `null` and resolved on first playback.
4. A lightweight content signature (source URI + size + modified time) detects duplicates before writing to Realm.
5. Successful imports create a `Video` record and queue a thumbnail generation hook (stubbed for v1).
6. Queue status is exposed to the UI through `useImportQueue`, enabling progress chips and cancellation in the future.

## Extending the app

- **Collections**: The Realm schema already defines a `Collection` model. Implement a dedicated screen and connect it to `Video` IDs to build curated playlists.
- **Advanced markers**: The marker model supports `tEndMs` and notes. Expand the UI to manage full-range annotations.
- **Thumbnails**: The `thumbnails.ts` stub provides the entry point for future image extraction. Plug in a native thumbnail module and persist thumbnail paths in Realm.
- **Share sheet imports**: The `VideoSource` enum already includes `shareSheet`; add a native share extension that forwards content URIs to the import queue.

## Troubleshooting

- If imports silently fail on Android, confirm that the URI returned by the picker is readable by `react-native-fs`. Some OEM file managers require `persistableUriPermission`; integrate `react-native-permissions` and `Intent.FLAG_GRANT_READ_URI_PERMISSION` as needed.
- For large files, the queue runs in the JS thread but yields between async steps—keep the UI responsive by monitoring the job list. Native module integration (e.g., background services) can be added later if throughput becomes an issue.
- When schema changes are under development, uninstall the app or increment the schema version with a proper migration to avoid `RealmSchemaVersionMismatch` errors.
